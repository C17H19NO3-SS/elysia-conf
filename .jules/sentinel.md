## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.
## 2024-05-15 - [CRITICAL] Prevent Directory Traversal in File Writing/Reading Paths
**Vulnerability:** The logger file path (`config.logger.file`) and error boundary file paths (`config.errors?.[errorCode]`) were being used directly in `Bun.write` and `Bun.file` operations without proper normalization and base directory bounding. This permitted directory traversal strings like `../../../../etc/passwd` to either write log files into or read content from sensitive system locations.
**Learning:** Even internal configuration elements such as log file definitions or error template mapping definitions need to be securely handled before invoking filesystem APIs, specifically enforcing root/cwd boundary constraints.
**Prevention:** Implement and enforce a standard path sanitization helper that sanitizes directory traversal string combinations (`../`) and validates that the fully resolved path continues to reside within the intended base directory context (like `process.cwd()`).
