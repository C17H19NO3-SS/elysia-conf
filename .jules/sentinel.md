## 2024-05-24 - [Path Traversal in Elysia Custom Config Logger and Error Boundaries]
**Vulnerability:** The custom configuration parser allowed path traversal payloads via `logger.file` and `errors[statusCode]` values, which were passed unvalidated to `Bun.write` and `Bun.file`. This enabled an attacker reading or writing arbitrary files outside `process.cwd()`.
**Learning:** In Elysia applications directly consuming raw paths into file operations (e.g. `Bun.file`), path values must be explicitly sanitized to remove absolute paths and directory traversal payloads (`..`) before resolving against a safe `baseDir`. The fact that Bun returns 404 (or throws ENOENT when processed) instead of inherently restricting access based on app root means path security must be enforced manually.
**Prevention:** Always implement a `safeResolve` utility that normalizes the input path, strips root directory slashes (`/`), and asserts `resolvedPath.startsWith(baseDir + sep)` when dealing with arbitrary file path configurations.
