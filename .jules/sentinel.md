## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.
## 2025-02-14 - Directory Traversal in File Output and Error Templates
**Vulnerability:** The configuration parser allowed arbitrary file paths for `logger.file` and `errors` boundary configurations. This exposed the system to directory traversal vulnerabilities, allowing malicious actors to write log files or read sensitive files (like `/etc/passwd`) outside the application's intended root directory.
**Learning:** Configurable paths passed dynamically into `Bun.write` and `Bun.file` must always be explicitly sanitized and resolved against a known base directory, as raw user input in `server.config` can easily include traversal paths like `../` or `/var`.
**Prevention:** Implement a standard `getSafePath` utility that uses `path.resolve` and enforces boundary checks via `resolvedPath.startsWith(baseDir + path.sep)`. Always pass dynamically configured paths through this sanitization before they hit file system APIs.
