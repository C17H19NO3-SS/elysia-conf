## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.
## 2024-05-18 - [Path Traversal in Asset and Error File Resolution]
**Vulnerability:** The configuration parser allowed arbitrary file reads (and potentially writes for the logger) via Path Traversal by directly using `Bun.file()` and `staticPlugin({ assets: ... })` with user-supplied strings like `../../../../etc/passwd` in the `errors`, `static`, and `logger` configuration blocks.
**Learning:** `Bun.file()` and `Bun.write()` do not natively protect against Path Traversal and resolve paths relative to the current working directory. The static plugin also accepts absolute paths or relative paths traversing out of the expected directory. Security boundaries must be enforced manually.
**Prevention:** Implement a strong path validation utility (e.g., using `path.resolve` and checking if it `startsWith(baseDir + sep)`) and ensure all dynamic paths from configuration files are sanitized before any filesystem interactions.
