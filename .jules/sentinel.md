## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.
## 2025-02-28 - [Path Traversal in Bun.file/Bun.write calls]
**Vulnerability:** The configuration parser allowed user-specified paths for `logger.file` and `errors` to be passed directly to `Bun.write` and `Bun.file` without sanitization or path bounding, allowing arbitrary file reading/writing outside the intended directory via path traversal (e.g., `../../../../etc/passwd`).
**Learning:** Any dynamically provided configuration path must be treated as untrusted and strictly bounded to a base directory like `process.cwd()` before being passed to low-level runtime filesystem operations.
**Prevention:** Always use standard path resolution (e.g., `path.resolve(baseDir, userInput)`) and explicitly validate that the resulting absolute path resides strictly within the intended base directory using `resolvedPath.startsWith(baseDir + path.sep)` or equals `baseDir`. Do not rely on regex sanitization.
