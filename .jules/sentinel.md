## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.

## 2024-05-24 - [CRITICAL] Prevent directory traversal execution loops on the static router path resolution
**Vulnerability:** Path traversal vulnerability existed where custom file paths parsed from the configuration (such as `logger.file` and `errors` fallback files) were passed directly to `Bun.write` and `Bun.file` without sanitization. This allowed attackers or malicious configurations to read or write arbitrary files on the host file system using paths like `../../../../etc/passwd` or absolute paths like `/etc/passwd`.
**Learning:** Even though the framework uses `staticPlugin` for the main asset serving which might have some protections, custom user configurations defining explicit files for logging or error boundaries still execute raw filesystem operations in Bun.
**Prevention:** Always sanitize, normalize, and bound file paths dynamically derived from configuration values. Use a robust utility like `resolveSafePath` that strips absolute path prefixes (`/`, `C:\`) and mitigates `../` relative path traversal strings before passing them to internal core executions.
