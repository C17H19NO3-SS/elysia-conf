## 2023-10-27 - [Prototype Pollution via Lexer Parser]
**Vulnerability:** Prototype pollution vector found in `src/lib/parser.ts` where arbitrary keys parsed from the configuration format (like `__proto__`, `constructor`, `prototype`) could be assigned directly to object structures (`config` or `currentBlock`).
**Learning:** Because the parser maps configuration keys to Javascript object properties natively without sanitization, malicious blocks or assignments allow attackers to pollute the global Object prototype context across the Node/Bun environment.
**Prevention:** Explicit validation must be enforced on all dynamic key variables fetched from token streams before they are used as object properties to ensure they are not reserved Javascript metaproperties.
## 2023-10-27 - [Path Traversal in Logger and Error Boundaries]
**Vulnerability:** Path traversal vulnerability found in `src/index.ts` where arbitrary file paths parsed from the configuration format (like `config.logger.file` and `config.errors[errorCode]`) were directly passed to `Bun.write` and `Bun.file` without sanitization. This allowed absolute paths and directory traversal sequences (like `../`) to access or modify files outside the intended directories.
**Learning:** Because the parser accepts any string for file paths and directly passes them to system I/O operations, malicious configurations could read sensitive files (e.g., `/etc/passwd` via error boundaries) or write arbitrary files (via logger).
**Prevention:** Implement a `safePath` utility that strips absolute path prefixes and resolves paths against a strict base directory (like `process.cwd()`), validating that the final resolved path stays within the intended directory bounds.
